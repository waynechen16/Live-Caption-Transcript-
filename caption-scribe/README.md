# Caption Scribe 字幕同步翻譯（DOM 版）

自 **meeting-scribe-english-extension** 的做法衍生：同樣的字幕面板（原文＋繁中＋英文）、
同樣的翻譯引擎（DeepL / Gemini 擇一）、同樣的匯出與錄音——
但**字幕來源改為 DOM capture**：直接擷取頁面上顯示的即時字幕
（Teams / Webex / Google Meet 自動偵測，其他網站可手動框選字幕區域；框選過的網站以框選為準）。

Chrome 和 Edge 都可以用（同一套檔案，不用修改）。

## 功能（v1.1）

- **講者名稱**：直接用字幕上顯示的真實姓名（chip 自動配色）；平台沒給名字時
  會嘗試從「名字: 內容」前綴或區塊結構解析，仍解析不到才顯示「字幕」
- **手動框選字幕區域**：任何網站都可用；框選過的網站**永遠優先**用框選位置，
  沒框選才用內建的 Teams / Webex / Meet 預設位置；popup 有「清除框選」還原
- **Google Meet**：支援會議中的即時字幕（Captions）；若 Meet 改版導致抓不到，
  用「框選字幕區域」點選字幕區塊即可
- **中英夾雜**：只翻譯英文、中文部分原樣保留。例：原文「這是 Apple.」→ 譯文「這是蘋果.」
  （Gemini 引擎按此規則執行；DeepL 以中文為目標語言時行為即近似如此）
- **翻譯開關**：popup 勾選「啟用翻譯」；關閉時純記錄字幕原文（不需要 API Key），
  仍可從面板匯出存檔
- **錄音（MP3）**：popup 勾選「錄音」後開始擷取，即錄下分頁聲音（遠端與會者）；
  再勾「連同我的麥克風」可把自己的發言混音錄入（echoCancellation 防回授，戴耳機最佳）。
  錄音啟動後，浮動面板會多出「音檔」按鈕，隨時可下載 MP3（40kbps 單聲道 ≈ 18MB/小時），
  存檔後繼續錄，之後再存仍包含全程
- **匯出**：原文 / 中文 / 英文（.txt，含時間戳與講者名）＋ Markdown 會議記錄 ＋ MP3
- 沿用參考版：可拖曳半透明面板、原文先上譯文補入、記錄存瀏覽器本機（重整後面板還原歷史）

## 安裝（開發模式）

1. `chrome://extensions`（Edge：`edge://extensions`）→ 開啟「開發人員模式」
2. 「載入未封裝項目」→ 選這個資料夾
3. 點外掛圖示 → 翻譯設定裡選引擎並填 API Key（只用純記錄模式則免填）

## 使用

1. 會議中開啟平台內建「即時字幕 / Live captions」（字幕要顯示在畫面上）
2. 點外掛圖示，按需要勾選「啟用翻譯 / 錄音 / 麥克風」→「開始擷取」
3. 半透明面板出現：原文即時顯示（半透明＝還在逐字修正），定稿後補入黃色繁中與英文
4. 面板上直接按「原文 / 中文 / 英文 / MD / 音檔」匯出；「清除」會連錄音一起重置

## 運作原理

- MutationObserver 監聽字幕區域，逐字修正**就地更新**同一條目（不會重複）
- 條目閒置 1.8 秒視為「定稿」→ 送 background 翻譯 → 譯文補回同一條目；
  定稿後字幕又延長（長停頓後續講）→ 自動回到未定稿狀態，重新定稿後重翻
- 錄音走參考版架構：background 取 tabCapture streamId → offscreen document
  getUserMedia（＋麥克風混音）→ AudioWorklet PCM → lamejs 即時增量編碼 MP3

## 已知限制

- 擷取品質取決於平台字幕品質（這是平台 STT 的結果，非本外掛辨識）
- 只能抓到「頁面上顯示的字幕」；對方沒開字幕就沒有來源
- 分頁重整後需再按一次「開始擷取」；錄音資料存在記憶體，外掛重載或瀏覽器
  重啟會遺失尚未下載的錄音，長會議建議中途先按「音檔」存一份
- 各平台介面改版可能使自動偵測失效 → 用「框選字幕區域」手動指定
- API Key 存在瀏覽器本機；翻譯內容會送到你選的翻譯服務（DeepL / Google）
